# V9938 / V9958 — the spec Ok-Prompt implements

Written from the V9938 Technical Data Book (TDB), map.grauw.nl and
openMSX's `VDP.cc`, `VDPCmdEngine.cc`, `SpriteChecker.cc`,
`BitmapConverter.cc`, and checked against what C-BIOS 0.29 does at boot.
**[U]** marks points that are uncertain, with the default chosen.

## 0. What C-BIOS uses at boot

C-BIOS MSX2/2+ runs CHGMOD and friends from its SUB-ROM (`video.asm` built
for V9938, the V9958 treated the same):

1. `init_vdp`: reads S#0; R#1=E0h, R#3=80h, R#4=01h, R#8=08h (TP=0).
2. SETRD/SETWRT write R#14=0 before each address; SCREEN 4+ VRAM calls
   (NSETWR/NSETRD) compute R#14 from ACPAGE.
3. `chgmod_finish`: R#0-R#7 direct; R#17=08h and R#8-R#14 by OTIR to 9Bh;
   R#17=18 and R#18-R#23. LN set for SCREEN >= 5; R#13=0, R#23=0.
4. Logo: CHGMOD 5 (R#0=06h, IE0, R#2=1Fh, R#5=EFh, R#11=0, R#6=0Fh; sprites
   hidden with Y=217); CLS by **HMMV** polling **S#2 CE** (via R#15=2);
   palette by R#16=0 + 32 bytes to 9Ah; **HMMC** with R#17=32 and OTIR of
   R#32-R#46 (CLR = first data byte), then R#17=80h|44 and data bytes while
   CE=1 (it never checks TR; extra bytes after the end must be harmless);
   text through GRPPRT: **LMMC+TIMP** (B8h) with the first pixel pre-written
   in R#44 and 63 more R#44 writes without polling TR. Palette fades with
   HALT (vblank IRQ in G4).
5. VRAM size probe: R#14=4, write 76h at 0, read back → MODE bit 2 (128K).
   Needs 17-bit addressing and the read-ahead.
6. `vram_clear`, CHGMOD 1, INIPLT (palette + copy to VRAM 2020h).
7. Other C-BIOS commands: LINE (NVBXLN), LMMV (NVBXFL), LMMM (BLTVV), LMMC
   (BLTVM, polls CE then TR), LMCM (BLTMV, reads S#7).
8. TEXT2: CHGMOD 0 with LINL40 > 40: R#0 |= 04h, R#1 = (R#1&E7h)|10h,
   R#2 = (NAMBAS>>10)|03h, R#4 for patterns at 1000h. It never sets the
   blink table, so no blinking under C-BIOS.

## 1. Ports 98h-9Bh

State: `ptr` (14 bits), `latch`, `latched`, `readAhead`, `palLatch`,
`palPhase`. Logical address `A = ((R#14&7)<<14) | ptr`; physical
`P = planar ? ((A<<16)|(A>>1)) & 0x1FFFF : A`, planar in G6 and G7.

- 98h write: `vram[P]=v; readAhead=v; increment(); latched=false`.
- 98h read: `r=readAhead; readAhead=vram[P]; increment(); latched=false`.
- `increment()`: `ptr=(ptr+1)&0x3FFF`; when it wraps to 0 and the mode has
  M4 or M5 (T2, G3-G7), `R#14=(R#14+1)&7`. In T1/G1/G2/MC it wraps in the
  16K window R#14 selects.
- 99h write: first byte only latches (unlike the TMS9918A, `ptr` is not
  touched). Second byte: bit 7 → write register `v&0x3F` with the latch
  (24, 28-31, >=47 ignored; 25-27 only on V9958); else
  `ptr=((v&0x3F)<<8)|latch`, and if bit 6 is clear (read), prefetch:
  `readAhead=vram[P]; increment()`.
- 99h read: S#(R#15&15) with the side effects below; `latched=false`.
- 9Ah write: first byte `0RRR0BBB` latched, second `00000GGG`:
  `palette[R#16]=((v&7)<<8)|(latch&0x77)` (0x0GRB), R#16 += 1 (mod 16).
  A write to R#16 resets the phase.
- 9Bh write: `n=R#17&0x3F`; if n != 17 write register n; if R#17 bit 7
  (AII) is clear, `R#17=(R#17&0x80)|((n+1)&0x3F)`.

Write masks R#0-23: `7E 7F 7F FF 3F FF 3F FF | FB BF 07 03 FF FF 07 0F |
0F BF FF FF 3F 3F 3F FF`; V9958 R#25-27: `7F 3F 07`. Command registers are
masked by the engine.

## 2. Registers and status

| R# | Bits |
|---|---|
| 0 | b4 IE1 (line interrupt), b3 M5, b2 M4, b1 M3 |
| 1 | b6 BL (display on), b5 IE0 (vblank), b4 M1, b3 M2, b1 SI, b0 MAG |
| 2 | name / bitmap page base A16-A10 |
| 3 + 10 | colour table A13-A6 (R#3), A16-A14 (R#10 b2-0); T2 blink table |
| 4 | pattern generator A16-A11 |
| 5 + 11 | sprite attributes A14-A7 (R#5), A16-A15 (R#11 b1-0) |
| 6 | sprite patterns A16-A11 |
| 7 | text colour b7-4, backdrop b3-0 (G7: whole byte GRB332; G5 split) |
| 8 | b5 TP (colour 0 opaque = palette 0), b1 SPD (sprites off) |
| 9 | b7 LN (212 lines), b2 EO, b1 NT (PAL, 313 lines) |
| 12, 13 | T2 blink colours; blink periods (on b7-4, off b3-0, x10 frames) |
| 14 | VRAM A16-A14 |
| 15 | status pointer |
| 16 | palette index |
| 17 | b7 AII, b5-0 indirect target |
| 18 | set adjust (nibble n → offset (n^7)-7) |
| 19 | line interrupt line |
| 23 | vertical scroll |
| 32-46 | command engine |

Reset: registers 0; S#2 has b3-2 = 1 always; S#1 ID 0 (V9938) or 2 (V9958,
reads 04h); palette = MSX2 default (§5.6).

| S# | Contents | Read effect |
|---|---|---|
| 0 | b7 F, b6 5S/9S, b5 C, b4-0 sprite number | clears F, 5S, C |
| 1 | b5-1 ID, b0 FH | clears FH |
| 2 | b7 TR, b6 VR, b5 HR, b4 BD, b3-2 =1, b1 EO, b0 CE | — |
| 3/4 | collision X (S#4 = FEh \| b8) | — |
| 5/6 | collision Y (S#6 = FCh \| b9-8) | S#5 read zeroes X/Y |
| 7 | colour (POINT, LMCM) | LMCM: hands over the pixel, fetches the next |
| 8/9 | SRCH border X (S#9 = FEh \| b8) | — |
| 10-15 | FFh | — |

`irq = (F && IE0) || (FH && IE1)`. Turning IE1 off clears FH's pending IRQ.

## 3. Modes and tables

M1=R#1 b4, M2=R#1 b3, M3=R#0 b1, M4=R#0 b2, M5=R#0 b3.

| Mode | M1M2M3M4M5 | SCREEN | Width | Pixels/byte | Sprites | Planar |
|---|---|---|---|---|---|---|
| T1 | 10000 | 0 (W40) | 240 | char | none | no |
| T2 | 10010 | 0 (W80) | 480 | char | none | no |
| MC | 01000 | 3 | 64x48 blocks | — | mode 1 | no |
| G1 | 00000 | 1 | 256 | char | mode 1 | no |
| G2 | 00100 | 2 | 256 | char | mode 1 | no |
| G3 | 00010 | 4 | 256 | char | mode 2 | no |
| G4 | 00110 | 5 | 256 | 2 (hi nibble left) | mode 2 | no |
| G5 | 00001 | 6 | 512 | 4 (b7-6 left) | mode 2 | no |
| G6 | 00101 | 7 | 512 | 2 | mode 2 | yes |
| G7 | 00111 | 8 (10-12) | 256 | 1 (GRB332) | mode 2 | yes |

192 or 212 lines in all (T1/T2: 24 or 26.5 rows). Other combinations:
backdrop, no sprites.

Addresses are ANDed, not added; `l = (y + R#23) & 0xFF`:

- T1/G1 name `((R2&0x7F)<<10) | idx` (idx = row*40+col or row*32+col,
  row = l>>3); pattern `((R4&0x3F)<<11) | name<<3 | l&7`; G1 colour
  `(R10<<14) | (R3<<6) | name>>3`.
- T2 name `(((R2&0x7F)<<10)|0x3FF) & (0x1F000 | (row*80+col))`; blink
  `(((R10&7)<<14)|(R3<<6)|0x1FF) & (0x1FE00 | (row*10 + col>>3))`, bit
  `7-(col&7)`.
- MC pattern `((R4&0x3F)<<11) | name<<3 | (row&3)<<1 | (l>>2)&1`.
- G2/G3: `ch = (l>>6)<<8 | name`; pattern
  `(((R4&0x3F)<<11)|0x7FF) & (0x1E000 | ch<<3 | l&7)`; colour
  `(((R10&7)<<14)|(R3<<6)|0x3F) & (0x1E000 | ch<<3 | l&7)`.
- G4 byte `(((R2&0x7F)<<10)|0x3FF) & (0x18000 | l<<7 | x>>1)`; G5 same with
  x>>2.
- G6/G7 logical `((R2&0x20)<<11) | l<<8 | xb` (xb = x>>1 or x), read at
  `phys(L) = ((L<<16)|(L>>1)) & 0x1FFFF`.
- Sprites mode 1: SAT `((R11&3)<<15)|(R5<<7)`, patterns `(R6&0x3F)<<11`.
  Mode 2: `B = ((R11&3)<<15)|(R5<<7)|0x7F`; attribute i at
  `B & (0x1FC00|0x200|i)`, colour j (sprite*16+line) at `B & (0x1FC00|j)`
  (SAT − 200h).
- G6/G7 apply `phys()` to every access: CPU, commands, renderer, sprites.
  G7 pixel `((x&1)<<16) | (y&511)<<7 | x>>1`; G6 `((x&2)<<15) | y<<7 | x>>2`.

## 4. TEXT2 and blink

80 x 6-pixel characters (bits 7-2) in a 512 line (16 px borders). Colours
R#7; blinking characters (bit set and `blinkState`) use R#12.
R#13 write: if both nibbles non-zero, `blinkState=true`,
`count=(v>>4)*10`; else `blinkState=(v&0xF0)!=0`, `count=0`. Each frame:
`if (count && --count==0) { blinkState=!blinkState; count=(state?on:off)*10 }`.
[U] The same state alternates pages in G4-G7 with EO; low priority.

## 5. Lines, colours, interrupts

- Picture lines 0..displayLines-1 (192/212, latched with NT at frame
  start); F and VR at line displayLines; 262/313 lines of 228 cycles.
- R#23 scrolls name/pattern lines and the bitmap within its page; sprites
  compare against the scrolled line. Read per line.
- R#18 set adjust: framebuffer offsets (phase 2).
- Border: palette[R#7&15]; G5 even/odd pixels from R#7 b3-2 / b1-0; G7 R#7
  as GRB332; BL=0: whole line border, no sprites.
- TP=0: colour-0 background pixels show the backdrop; TP=1: palette[0].
- Palette 9-bit, RGB8 = v*255/7. MSX2 default (0xGRB, entries 0-15):
  `000 000 611 733 117 327 151 627 171 373 661 664 411 265 555 777`.
  G7 pixel `GGGRRRBB` (B expanded to 3 bits as (b<<1)|(b>>1)). G7 sprite
  colours (0xGRB): `000 002 030 032 300 302 330 332 472 007 070 077 700 707
  770 777`. On MSX2 every mode uses the palette registers.
- Line interrupt: after line `line` of the frame, if
  `line == (R19 - R23) & 0xFF` set FH.
- HR: `cycleInLine >= 228 - (text ? 67 : 52)`; VR: `line >= displayLines`.

## 6. Sprites

Off with SPD, in text modes, or BL=0. Size 8/16 x MAG; 16x16 uses
`pattern&0xFC`, left half bytes 0-15, right 16-31. Row test
`dy = (l - Y - 1) & 0xFF`, visible if `dy < size`.

- Mode 1 (G1, G2, MC): as TMS9918A; end at Y=D0h; 4 per line; 5th sets 5S.
- Mode 2 (G3-G7): end at Y=D8h; 8 per line, 9th sets 9S. Per line colour
  byte at colour(sprite*16 + row): b7 EC (X−32), b6 CC, b5 IC, b3-0 colour.
  CC: a CC=0 sprite and the CC=1 sprites after it form a group whose pixels
  OR their colours; a CC=1 sprite with no CC=0 before it is not shown.
  [U] CC pixels outside the CC=0 sprite still show their own colour.
  CC=1 or IC=1 sprites never collide. Colour 0 drawn only with TP.
  Collision: C, coordinates latched when C was clear: S#3/4 = X+12,
  S#5/6 = line+8.
- G5: sprite pixel is 2 screen pixels, palette[(c>>2)&3] then palette[c&3];
  G6: palette[c] for both; G7: the G7 sprite colours.

## 7. Command engine

R#32/33 SX (9 bits), R#34/35 SY (10), R#36/37 DX (9), R#38/39 DY (10),
R#40/41 NX (10), R#42/43 NY (10), R#44 CLR, R#45 ARG (b3 DIY up, b2 DIX
left, b1 EQ, b0 MAJ), R#46 CMD (b7-4 command, b3-0 logical op; writing it
starts the command). R#44 write: `COL=v; transfer=true`; feeds HMMC/LMMC.

| Mode | Width | px/byte | mask | Y mask | address |
|---|---|---|---|---|---|
| G4 | 256 | 2 | 0F | 1023 | `y<<7 \| x>>1`, nibble `(~x&1)<<2` |
| G5 | 512 | 4 | 03 | 1023 | `y<<7 \| x>>2`, shift `(~x&3)<<1` |
| G6 | 512 | 2 | 0F | 511 | `phys(y<<8 \| x>>1)` |
| G7 | 256 | 1 | FF | 511 | `phys(y<<8 \| x)` |

- Clipping: NX=0 → full width; run clipped at the edge in the DIX
  direction (`DIX ? min(NX, X+1) : min(NX, W−X)`, both operands for
  copies); NY=0 → 1024; DIY up clips `min(NY, Y+1)`; down wraps.
- Logical ops on pixels (c source or CLR, d destination): 0 IMP c, 1 AND,
  2 OR, 3 XOR, 4 NOT ~c; 5-7 no write; 8-C as 0-4 but skip when c==0
  (TIMP...); D-F no write. High-speed commands ignore the op.
- Commands: STOP (0-3); POINT (4) S#7 = point(SX,SY); PSET (5); SRCH (6)
  from SX in the DIX direction for `(point==CLR) XOR EQ`, BD and S#8/9;
  LINE (7) Bresenham with NX major, NY minor, MAJ picks the major axis,
  NX+1 pixels, DY updated; LMMV (8); LMMM (9); LMCM (A, via S#7); LMMC (B,
  via R#44); HMMV (C); HMMM (D); YMMM (E, from DX to the edge, NX
  ignored); HMMC (F, bytes via R#44). Afterwards NY = NY − rows done, DY
  (and SY for copies) moved by rows*TY; SX, DX, NX unchanged.
- LINE: `ASX=((NX−1)>>1)&1023; ANX=0; x=DX;` loop: pset(x,DY); MAJ=0:
  `x+=TX; if (ASX<NY) {ASX+=NX; DY+=TY}`; MAJ=1: `DY+=TY; if (ASX<NY)
  {ASX+=NX; x+=TX}`; `ASX=(ASX−NY)&1023`; end when `ANX++==NX` or x leaves
  0..W−1.
- Transfers (instant mode): HMMC/LMMC start with CE=1, TR=1, and consume
  a pre-written R#44 at once; each R#44 write moves one byte/pixel; CE=0
  at the end. LMCM loads the first pixel into S#7 at start; each S#7 read
  loads the next; CE=0 when the last is loaded.
- v1: instant execution (CE clears in the R#46 write). Breaks only
  software that paces itself on blit time.
- Modes other than G4-G7: no write, CE=0 (V9958 with R#25 CMD: 256 px,
  1 byte/pixel, linear `((y&511)<<8)|x`).

## 8. V9958

R#25: b6 CMD, b4 YAE, b3 YJK, b1 MSK (left 8 px border), b0 SP2.
Horizontal scroll `S = R#26*8 − R#27` dots (256-space), wraps at 256 (512
with SP2); screen x shows logical (x+S); sprites do not move.
YJK (G7 + YJK): 4 bytes p0..p3 → 4 pixels; `y=p>>3`;
`k=(p0&7)+((p1&3)<<3)−((p1&4)<<3)`, `j=(p2&7)+((p3&3)<<3)−((p3&4)<<3)`;
`r=clamp(y+j)`, `g=clamp(y+k)`, `b=clamp(trunc((5y−2j−k+2)/4))` in 0..31.
Note J = K = 0 is not grey: blue is (5Y + 2) / 4 (Y = 16 gives 16, 16, 20).
YAE: a byte with b3 set is `palette[p>>4]` instead. S#1 ID 2.

## 9. Framebuffer

576 x 240: 512 + 2x32 wide (256-pixel modes doubled), 212 lines at rows
14..225, 192 lines at rows 24..215. The MSX1 TMS keeps 288x224.
